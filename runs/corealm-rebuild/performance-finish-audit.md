# Native foliage performance audit

Read-only source and existing-report audit, September 4, 2026. No code, browser, build or test changes. This is a prioritization report, not acceptance evidence. The 96 m generation grid, seeded placement order, saved forest IDs, native topology, density, materials and wind remain requirements.

The largest demonstrated cost is native shrub and fern geometry submitted in the colour pass. The next useful work is to eliminate invisible instances and repeated vertex work. Another round of smaller static shards would trade more draw calls for fewer boundary instances without resolving the expensive foliage that actually intersects the view.

## What the evidence establishes

The accepted 24 m tree and 12 m understory partition reduced whole-world submissions substantially. Coldbrace improved from 270.094 M to 156.790 M triangles and from 48.3 to 33.4 ms median. Lower quarry improved from 484.791 M to 215.601 M and from 77.9 to 38.4 ms, while draw calls rose from 517 to 1,564. These are short diagnostic samples, not stable hardware-wide frame-rate results. See [acceptance.md](./acceptance.md).

## Current rendering costs

`WorldScene.scatterInstanced()` creates one `InstancedMesh` per source primitive and spatial shard. `finalizeScatterBounds()` expands aggregate bounds for wind. Three tests the aggregate sphere once per camera pass, then submits every slot when that sphere intersects. There is no per-instance frustum rejection inside these scatter meshes. A 12 m shard containing 102 shrub instances can therefore submit 3.313 M leaf triangles even when only some shrubs intersect the image. Distance residency uses the shard's horizontal box, which is also conservative.

The source models are expensive by design. `tools/data/corealm-nature.json` records 36,869 triangles and 1,624 laminae for shrub 2, 26,088 triangles for fern 1, and roughly 118,000 to 147,000 triangles per tree. `blade()` in `tools/build-corealm-nature.ts` emits 20 triangles for a six-segment curved leaf. That topology produces the accepted curved, lobed silhouette. The existing strict topology study did not identify a useful lossless reduction; reducing segment counts or deleting leaves would change the requirement.

Native leaves are opaque, double-sided geometry. The generator does not enable glTF alpha blending or masking. Grass cards have a separate alpha-test path. Setting `forceSinglePass` on native leaves therefore cannot remove a second colour pass, because Three's two-pass rule applies to transparent double-sided materials. Switching native leaves to `FrontSide` would make reversed leaf faces disappear. Double-sided rasterization still costs fragment work, but it does not double the reported triangle count automatically.

Every submitted wind vertex evaluates two sine functions, a local height weight and instance/world-origin transforms. `WIND_VERTEX_BODY` in `materials.ts:503` repeats those calculations in the colour shader and the matching custom shadow shader. This is a concrete high-volume workload. There is no supplied GPU profile proving how much time it consumes.

Colour fragments also pay for authored albedo, normal and roughness maps, standard lighting and the player reveal shader. `foliageOcclusion.ts` contains a conditional `discard` for the player opening even though native materials are otherwise opaque. Its cost and any effect on early depth rejection require measurement. It must not be confused with leaf-card alpha overdraw.

Shadows use one directional map covering 96 m at 2048 pixels and update each frame. Installed Three 0.185.1 maps the configured `PCFSoftShadowMap` constant to `PCFShadowMap`. Native tree bounds affect both camera passes; ordinary understory generally does not cast. Wind and moving actors make unconditional shadow-map caching incorrect. A camera-frustum-only visibility flag would also erase off-camera trees whose shadows fall into view.

## Safest optimization order

1. Add per-instance rejection for native understory while preserving the existing placement storage. Test an immutable source-matrix array plus a compact visible matrix buffer per asset/material group. Frustum-test each plant's native bound with wind margin, write only surviving matrices and set the draw count to that prefix. Keep resident population separate from submitted population. Because these plants do not cast shadows, the initial implementation needs only the current colour camera. Update after the camera's world matrix is current, before renderer submission. Do not collapse rejected instances to zero scale, because Three still submits those slots. The current tree hide callback in `scatter.ts:1542` uses zero-scale matrices and would need stable placement-to-render-slot indirection before trees can join this path.

2. Benchmark `BatchedMesh` as the alternative to matrix compaction, not as an assumed improvement. The entity renderer already uses its per-object camera and shadow culling, opaque sort policy and wind-expanded bounds in `entityViews.ts:4490`. The wind shader already handles `USE_BATCHING`. A material/attribute-compatible batch can contain exact native geometry and visibility flags without changing any model. Stock batching replaces instanced reuse with a multi-draw entry per visible instance and adds four matrix-texture fetches plus an indirect-index fetch in the vertex shader. It also copies source geometry into each batch. A separate batch per tiny shard would duplicate large GLBs in GPU memory. Without `WEBGL_multi_draw`, Three loops over surviving instances and issues one ordinary draw per plant; it does not fall back to instancing. Retain an instanced path on those devices. Compare larger spatial batches against compact `InstancedMesh` groups. Neither branch earns acceptance merely by lowering Three's draw counter.

3. Remove invariant work from the native wind shader. For static placements, instance-origin phase does not change. Local vertex height does not change either. Precompute phase terms per instance and local-height terms per vertex, update shared time terms once per frame, and reconstruct the existing two waves with sine-angle addition. Keep the same phase constants, strength, height weighting and colour/depth implementation. This preserves the mathematical bend and topology; floating-point differences need a bounded motion comparison. Added attribute bandwidth may outweigh arithmetic savings, so compare GPU time before accepting it. A useful smaller first variant caches static origin/phase only. Do not move entire plants rigidly as a replacement for per-vertex bending.

4. Reduce static scene CPU work after measuring it. Scatter meshes retain Three's automatic local/world matrix updates even though their object transforms remain identity and their movement is in static instance matrices or shader wind. Freeze those object transforms after initialization. Preserve explicit updates for dynamic objects and any parent changes. Three still recursively visits children when these flags are disabled, so this saves compositions and multiplications rather than removing traversal. Full residency eventually loads every scatter tile, making static object count relevant even for hidden tiles. This is a secondary improvement, not evidence that CPU traversal explains the heavy views.

5. If fragment time remains large, compare front-to-back ordering within opaque foliage groups and make the player reveal calculation cheap outside its projected body rectangle. Preserve its dither and depth behavior. Global material-first ordering currently favors material locality; changing the whole renderer's opaque ordering could increase material switches. A depth prepass doubles native geometry work and is a poor default until a GPU measurement shows that fragment shading dominates.

Per-instance frustum rejection will mostly remove boundary waste. It cannot eliminate the detailed plants genuinely in view. If the remaining GPU cost is still dominated by hidden foliage behind quarry walls or ridges, conservative occlusion culling becomes the next substantial option. Prototype asynchronous occlusion queries on coarse, wind-expanded groups behind opaque terrain or structures. Keep unproven groups visible, invalidate stale results on relevant camera/occluder changes, and never use foliage with holes as a solid occluder. This is more involved than frustum rejection and should follow measured simpler work. GPU vertex clipping alone still runs the vertex shader for rejected instances and is not a substitute for dropping submissions.

There are three implementation traps to resolve before integrating either culling path. First, do not compact instance attributes in `onBeforeRender` or `onBeforeShadow`. `WebGLObjects.update()` uploads them before those hooks and caches the update once per frame. Prepare buffers before `renderer.render()`; shadow-casting instances need at least the union of colour and shadow frusta with one shared compact buffer. Second, `BatchedMesh` copies per-geometry bounds during `addGeometry()`. Pad those local bounds for wind before upload, as `entityViews.ts:4559` already does; aggregate padding alone is insufficient. Third, scatter disposal currently targets `InstancedMesh`. A batched path must dispose its copied buffers and matrix/indirect textures too. Source checks are in `node_modules/three/src/renderers/webgl/WebGLObjects.js`, `WebGLShadowMap.js`, `node_modules/three/src/objects/BatchedMesh.js` and `game/src/render/scene.ts:3073`.

## Measurement and integration requirements

The current `getRenderProfile()` counts submissions by wrapping `renderBufferDirect()`, renders an extra synchronous frame, and truncates output to 40 rows. It supplies neither GPU duration nor complete colour/shadow totals. `Renderer.render()` records requestAnimationFrame intervals over 90 frames, which include simulation, browser scheduling and rendering. The existing evidence cannot distinguish vertex, fragment, driver and JavaScript time.

Before selecting between compaction, batching and shader work, add full pass/asset totals before row truncation, visible/resident instance counts and CPU phase timings. Use nonblocking GPU timer queries when supported and discard disjoint samples. Record extension support, actual drawing-buffer resolution, renderer identity, settled residency and the exact camera. Measure without profiling hooks or screenshots inside the timed interval. Keep diagnostic shadow-off and lower-resolution comparisons temporary; they classify cost and are not accepted quality changes.

The next lab proof should retain the existing 1,024-shrub pose, add a dense fern fixture, and include all-visible, partial-frustum, turned-away and return views. Native triangle count per submitted instance must remain unchanged. Compare wind at matching times, native bounds, leaf gaps and source asset requests. Trees additionally need a camera-outside/shadow-inside case and natural harvest, depletion, saved return and regrowth with unchanged IDs. Once the root accepts that production path in the lab, integrate it into world rendering and repeat the existing forest/quarry poses. Current contracts remain root-owned.

Do not claim a frame-rate win from packed file sizes, a reduced draw counter, fewer triangles alone, or source review. No simplification, density reduction, tighter visible fog, shadow removal or resolution reduction is proposed as the production fix.
