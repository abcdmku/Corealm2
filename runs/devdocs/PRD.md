# Corealm dev docs app, JSON content store, and approval-based asset workflow

> Superseded direction, 2026-09-13: [SIMPLIFICATION_PLAN.md](./SIMPLIFICATION_PLAN.md) replaces the remaining migration sequence and conflicting legacy-parity, schema, formula, and editor requirements below. The user permits content and gameplay changes to consolidate authoring. This PRD remains historical context; preserving its old catalogs and outputs is no longer an acceptance goal.

## Context

Corealm2's gameplay content (399 items, 24 armor sets, 236 recipes, 472 enemy stat blocks, 214 creature species, 35 resources, spawns, NPCs, shops, quests, spells, audio cues) is hand-authored TypeScript under `game/src/content/`. About half the item ids are generated by template from tier tables, spawns are folded from a dozen tuple tables plus an override layer, and approval state is scattered across `manifest.json` acceptance blobs (207 of 804 assets, ~40 shapes), `art/item-icons/generated/registry.json`, `art/item-models/registry.json`, and per-batch `acceptance.json` files. The process around it is a PRD/brief/critic/lab-gate narrative in `AGENTS.md`, `skills/`, `runs/*/PRD.md`, and ~90 markdown files under `art/`. Sixteen bespoke promote scripts each write `manifest.json` their own way.

The user wants one local app that is the source of truth: browse and edit every item, set, creature, recipe, resource, spawn, NPC, shop, quest, spell and audio source; view GLBs and every animation on male/female bodies or creature rigs; upload candidate GLBs; approve or reject; leave notes and requests per entity or set that an agent later works; drag spawns on the world map. The same app in read-only player mode replaces the Astro player guide.

Decisions made by the user in this session:
- Content migrates to JSON data files. TS modules become loaders + validators exporting the same table names.
- Legacy removal is scoped to the asset pipeline. `docs/feature-lab.md` and `docs/world-authoring.md` stay as testing guides.
- v1 scope: items, sets, creatures, recipes, resources, spawn map, plus NPCs/shops/quests, spells, audio.
- Agent handoff is an open-requests list the agent reads on demand.
- React + Vite for the app. Map editing: drag pack centre and per-actor anchors, add/remove packs.
- The Astro guide is replaced by a read-only player mode of the same app, deployed by the existing CI.
- Armor approval is per set, with per-piece notes.

## Requirements (complete list)

### R1. Browsing
- Collections: Items, Sets, Creatures, Resources, Resource clusters, Recipes, NPCs, Shops, Quests, Spells, Audio, Assets (GLBs/packs/candidates), Map, Review queue, Requests.
- List views: search, group toggle (tier / type / region / skill / status per collection), status chips, open-request badge, missing-asset and missing-icon badges, counts, keyboard nav.
- Item detail: stats, icon (256 master + 48 game), model(s), sources (recipe that makes it, resource that yields it, creature that drops it, shop that sells it, quest that grants it), uses (recipes consuming it, set membership, tool/food role), provenance (pack, author, license, icon prompt), notes, requests, status, history.
- Set detail: five armor pieces with icons and per-piece status/notes, set bonuses, tier/style, 3D viewer on male and female with all pose clips and piece toggles, recipes for all pieces in one table, drop sources, candidate-vs-live compare.
- Weapons and kits: every tier has a kit (dagger, sword, shield, staff, wand, pickaxe, hatchet, rod) alongside its armor set. A Kits view groups them by tier and style; weapon detail shows the weapon equipped on either body playing the matching pose clip (`attack_melee`, `cast`, `mine`, `chop`, `fish`), grip/socket readout, derived damage/accuracy/speed from the gear formula, recipes and drop sources. Weapons can be added to a set viewer as main/off hand. Weapon approval is per weapon; kit view shows aggregate status.
- Creature detail: editable stat block plus computed combat level, model with every clip grouped by motion, editable loot table (drops with chance/quantity/exclusive group, marks), spawns list with map links, description, provenance, measured gait.
- Resource detail: yield item, bonus rolls, respawn, presentation assets (available/depleted), clusters on map.
- Recipe detail: inputs/outputs with icons, skill/level/tier/station/duration/xp, recompute-xp helper.
- NPC, shop, quest, spell, audio detail pages with editable fields and cross-links.

### R2. Editing
- Any authored field is editable inline; save validates (schema, cross-table, spawn formation) and shows diagnostics before writing. Blocking errors never write.
- Writes are atomic to JSON in the repo; git is the audit trail. Optimistic concurrency by file revision.
- Save-identity fields (ids, `count`, `legacyCount`, spawn record order) are read-only in the UI.
- Recompute helpers: gear stats from tier ladder, recipe xp from weight, drops from species/tier, set thresholds, formation anchors from count/radius. A `derivation` tag on a record means "formula-locked, test-checked"; deleting the tag means hand-tuned.
- Bulk actions on multi-select: set status, add note, retier.
- Balance derivations from the `equipment.ts` / `recipes.ts` / `enemies.ts` headers move verbatim to `docs/balance.md` and are also rendered in the app's Balance section next to the live parameters.

### R2b. Balance and derivation helpers (visible and editable)
- Every number a formula reads is data, not code: `game/content/data/balance/*.json` holds the tier ladders (`craftingTiers`, `gatheringTiers`), gear arithmetic constants (per-tier damage, accuracy, armour and health baselines, style factors, attack speeds from `equipment.ts`), recipe craft weights (the `W` table) and `recipeXp`/`healAmount`/`toolBonus` constants, creature material values, mark ranges, fantasy tier-scaling ratios, loot roll tables (`wildernessDrops`, `bossArmorDrops`, `regionalFabricDrops` inputs), set threshold rules (`defineSet` defence/health per tier), jewellery profiles, enemy TTK targets, and combat-level tuning targets.
- Formula code stays in `game/src/content/balance/*.ts` as pure functions `(params, input) => output`. The app has a Balance section with one page per formula: the parameter table (editable), the formula source rendered read-only with syntax highlighting, a worked example with live inputs, and a "recompute affected records" action that previews a diff across every record carrying that `derivation.kind` before writing.
- Editing a parameter never silently rewrites records. The record view shows "drifted from formula" when its values no longer match, with per-record apply/keep.
- `tests/content-derivation.test.ts` recomputes every tagged record from the JSON parameters and fails on drift, so the parameters and the records cannot disagree at commit time.

### R3. Notes and requests
- Notes per entity and per set: text, timestamp, label. A note can be flagged as an open request with a kind (art, balance, placement, audio, text).
- Requests view lists every open/claimed request across collections. CLI prints them for agents; agents claim and reply, never close or approve.

### R4. Assets and approval
- GLB viewer: manifest asset or candidate, orbit, clip list with play/pause/scrub/speed, bounds and size readout against manifest size, material list, wireframe.
- Upload GLB (drag-drop or picker) tied to a target entity and slot; server inspects (magic, sha256, animations, materials, size) and writes a candidate under `art/candidates/` with a catalogue entry.
- Status machine per candidate: candidate → approved → live; rejected with reason. Sets require male and female sign-off before approve. Promote copies bytes into `game/public/assets/models/...`, upserts the manifest entry with provenance and license, marks live.
- Icon status and prompt provenance per item; icon publish refuses unless approved.
- Review queue: candidates by state, open requests, recently changed files.

### R5. Map
- Background: `game/public/generated/world-map-detail-*.webp` and 600 px tiles, pan/zoom, world-metre SVG stage.
- Layers: spawn packs (centre, radius ring, numbered anchors, formation preview), regional packs, resource clusters, locations/towns, region bounds, resolved positions from a baked dump, locked derived spawns (fairy, coastal).
- Drag centre (anchors shift by delta), drag anchor (clamped inside radius), add pack (species picker, default count/radius, formation preview), remove pack, side panel for count/radius/activity/legacy override, undo/redo.
- Validation on save: count bounds (7–15, fixed 1–15), anchors inside region ∩ world ∩ radius, formation fits, overlap against reservations, asset radius known.

### R6. Player mode
- Same app, static build to `dist/`, read-only, all dev-only UI tree-shaken out, no notes/requests/candidates in the bundle.
- Replaces `docs-site/`, Astro, `tools/gen-docs.ts` markdown, and the guide half of `.github/workflows/docs.yml`.
- Reuses the game tooltip styling; landing page mirrors the old Codex index (Quests, People, Creatures, Regions, Items, Armor, Recipes, Resources, Skills, XP, Spells & shops).

### R7. Legacy removal and new agent rules
- Rewrite `AGENTS.md` around the JSON store and approval workflow; keep rules 5 and 7 at their numbers (cited by code comments).
- Delete the asset-review server, skills/, briefs/, process docs, per-batch review markdown, the 16 promote tools, and the model registry once the unified path exists.
- Seed statuses from legacy registries and manifest acceptance fields.
- Keep licensing validation, `runs/corealm*` (cited by ~86 code comments), and the 11 tests pinning `art/rebuild/candidates/**`.

### R8. UI quality
- Production-grade, modern dev/docs site: consistent design system, dark and light themes, responsive layout, keyboard navigation, command palette, smooth page and panel transitions, skeleton loading, optimistic saves with toasts, virtualised tables for the 400+ item lists, sticky detail headers, resizable side panels for the map and viewer.

## Architecture

### Content store (`game/content/`)
```
game/content/
  data/        shipped, hashed into the world revision, imported by game/src loaders
    items.json equipmentSets.json recipes.json resources.json gatheringTiers.json craftingTiers.json
    enemies.json enemyAliases.json lootTables.json creatures.json
    spawns/<regionId>.json (9 files)  resourceClusters.json  regionalPacks.json
    npcs.json shops.json quests.json dialogue.json spells.json spellRunes.json audio/catalog.json
  meta/        dev-only, NOT hashed, NOT importable from game/src (guard test)
    <collection>.meta.json   keyed by record id
    assets.meta.json icons.meta.json audio-sources.json
  README.md    format rules, key order, "run npm run content:check"
```
- Inside the Vite root so loaders use plain relative imports; outside `game/src` so `tools/lib/generation-revision.ts` can add `game/content/data/**` and exclude `meta/`.
- One file per collection (tsx cannot glob-import; a canonical formatter keeps one-record diffs). Spawns shard per region.
- Rule: if a loader reads it, it is data; if only humans or the app read it, it is meta.
- Meta record: `{ status: draft|candidate|approved|live|rejected, notes[{at,by,text,request?{id,kind,state:open|claimed|replied|closed,claimedBy?,reply?}}], approvals?{male,female} (sets), pieces?{slot:{note}} (sets), candidates[{candidateId,kind,sha256,file,bytes,size,animations,status,reasons?,uploadedAt,approvedAt?,promotedAt?,manifestId?,slot?,body?}], history[{at,by,action,detail}], sourceRefs[] }`.
- Record extras (inline, shipped): `catalog` (which sub-table a row came from, so `EQUIPMENT`, `REGIONAL_TIER_ITEMS`, `FOREST_CREATURE_REDESIGNS` etc. remain as filtered views), `derivation` (formula lock), `ladder` (tier ladder cell), `lootTableId`, `blockId`, `speciesId`, `stage` (registered vs labOnly), spawn `authored`, `legacyOverride`, `derived`, `source`.
- Enemies keep two id spaces: species id (`redbrush_fox`) and block id (`redbrush_fox_t1`). `enemyAliases.json` maps group ids to blocks with optional overrides and lineage.
- Spawn record = post-transform `EnemyGroupDef` + `habitat{...anchors,dressing}` (final formation output) + `authored` + `legacyOverride` + `derived`. Loader rebuilds `REGIONS[].enemyGroups`, `WORLD_HABITATS`, `LEGACY_ENCOUNTER_PLACEMENTS`, `SOURCE_REGIONS` groups from these. Rows with `derived` are ignored by the loader and regenerated; a test asserts no drift.
- Validator: hand-rolled combinators in `game/src/content/schema/core.ts` (`obj/str/num/int/bool/lit/arr/tuple/opt/rec/union/enumOf`, `parseCollection`), no zod. Each field carries optional metadata (`label`, `help`, `unit`, `readOnly`, `ref: 'item'|'asset'|...`) so the app builds forms from the schema. Cross-table checks stay in `game/src/content/validate.ts`.
- Balance parameters: `game/content/data/balance/{gear,recipes,sets,loot,enemies,jewelry,formation}.json` hold every constant the generators read. Generators move to `game/src/content/balance/*.ts` as pure functions `(params, input) => output` with no JSON imports; the loaders pass the JSON params in. Used by the app's Balance pages and by `tests/content-derivation.test.ts`.

## Risks and mitigations
- Save identity: ids, `count`, `legacyCount`, spawn order are load-bearing (`encounterActorId`, `FANTASY_ENCOUNTER_LINEAGE`, `mobSpawnCache` index check). `content:check` diffs id sets and order against HEAD and refuses without `--allow-identity-change`; UI marks them read-only.
- World bake: `game/content/data` must be in the revision hash; meta must not be. Parity tests prove anchors are numerically identical so `spawns/world` stays valid across the swap.
- Bundle budget: same bytes as the TS literals plus ~8 KB gzip of tags; well under the 1 MB gzip application budget. Dialogue can lazy-load later.
- Two Vite roots: `balance/*` and `schema/*` must never import JSON or `import.meta.env`.
- `<base href>` in player mode changes relative URL resolution; the `gameUrl()` grep test guards it. Known pre-existing hazard: `fabArmor.ts:35` uses a root-absolute texture URL (404s on Pages for the game too); optional one-line fix.
- Windows paths in submit/promote: reuse the `path.relative` guards already in `promote-finish-assets.ts`.
- Other sessions commit to main concurrently; rebase before each milestone merge and never touch another session's worktree.
