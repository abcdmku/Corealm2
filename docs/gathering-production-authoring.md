# Gathering and production authoring

This guide is the checklist for adding a gathering tier and its region. The level 1, 5, and 10 rows prove the pattern. Levels 20 through 70 should add content without adding tier branches to gathering, production, campfire, save, or UI systems.

## Source of truth

Keep each fact in one table.

| File | Owns |
| --- | --- |
| `game/src/content/gatheringProductionTiers.ts` | Canonical gathering requirements, drops, presentation, tier links, and campfire fuel |
| `game/src/content/items.ts` | Stackable materials, food, tools, and item values |
| `game/src/content/equipment.ts` | Equippable weapons, armour, requirements, bonuses, and values |
| `game/src/content/resources.ts` | Aggregates canonical tier resources with non-tier resource families |
| `game/src/content/recipes.ts` | The generated production matrix and shared recipe weights |
| `game/src/content/regions.ts` | Cluster count and placement through `resourceId`, plus fixed station placement |
| `game/public/assets/manifest.json` | Runtime asset IDs and CC0 pack metadata generated by the asset build |

`GATHERING_PRODUCTION_TIERS` connects these tables. Do not copy tier names, item IDs, or campfire numbers into a system or panel. The generated game guide reads the catalog, resources, recipes, and items directly.

## Add a tier row and its items

1. Choose the unlock level and region. Use the same value for `tier` and `reqLevel` unless the design explicitly adds an intra-tier unlock.
2. Add the resource items, raw and cooked fish, burnt fish, log, shaft, handle, bar, and other components to `items.ts`. Keep component IDs in lowercase snake case. Never reuse a shipped ID for a different item.
3. Add weapons, armour, tools, staff, wand, focus, fishing rod, and shield to `equipment.ts`. Supply equipment requirements and bonuses at the item level. A missing held appearance or icon is a content error, not a renderer fallback policy.
4. Add one `GatheringProductionTierDef` row. Fill every item and resource reference. The TypeScript shape is deliberately complete, so an omitted family fails before runtime.
5. Build the campfire row with the shared helper. Lifetime is `60 + 12 × tier` seconds. Fletching and Crafting each receive `round(gatherXp(tier) × 0.2)` XP. Log tier must not change cooking access or burn chance.
6. Check the recipe matrix produced for the new tier. Add new universal recipe families to the row builder once. Do not append a special recipe block for one tier.

Current recipe families expect one metal, one gem, one hide, and one wood family per tier. March Stone is the shared flux for levels 1, 5, and 10. A future design may keep it or supply another flux through the tier row, but the smithing system must not know which choice was made.

## Supply resource assets

Each `ResourceDef.presentation` supplies gameplay-scale presentation data.

| Field | Authoring rule |
| --- | --- |
| `availableAssetIds` | Add every active variant. The renderer chooses one deterministically from the entity ID. |
| `depletedAssetId` | Supply a real worked-out rock or stump when one exists. The renderer fallback is only for assets without a proper spent state. |
| `targetWorldSize` | Set the largest world dimension in metres at normal play scale. Do not repair a bad source scale in every region cluster. |
| `variantScale` | Keep the range narrow enough that interaction distance and silhouettes remain consistent. |
| `waterOffset` | Set fish below the canonical solved water surface. Do not derive water from terrain height or a separate circle calculation. |
| `materialTier` | Select the tier treatment for ore fractures, foliage, fish, ripples, and other procedural details. |

Import source files through `tools/build-assets.ts`. Pin the source URL, pack ID, `CC0-1.0` license, and archive SHA-256. OBJ and MTL sources must pass through the pinned conversion step before the normal GLB optimization. Runtime code loads the resulting manifest asset ID. It does not read an archive or a source filename.

Inspect active and depleted assets at normal camera distance. Ore needs readable embedded mineral fractures and a worked-out scar. A felled tree needs its matching stump. A fishing spot needs fish below the solved surface, a surface interaction proxy, and a faint recovery marker after depletion.

## Add region clusters

Add a `ResourceClusterDef` to the new region with only these fields:

```ts
{
  id: "stable_cluster_id",
  resourceId: "canonical_resource_id",
  count: 6,
  centre: [x, z],
  radius: 8,
  locationId: "nearby_route_location",
}
```

The cluster owns count, placement, radius, and location. The resource row owns skill, requirement, yield, assets, scale, and spent presentation. Do not reintroduce cluster aliases.

Interactable resources never belong in scatter rules. Scatter can place non-interactive vegetation and dressing. A gatherable node needs a stable entity ID, depletion state, respawn state, semantic metadata, collision, and save identity. Follow `docs/world-authoring.md` for canonical height, water, playable bounds, collision clearance, and authored-location rules.

Treat a shipped cluster ID as save data. Do not rename it when swapping an asset or tuning a presentation field.

## Add compatible stations

Recipes declare `stations: readonly StationKind[] | null`.

- Use one station kind for smelting, smithing, Crafting, and Fletching.
- Cooking fish accepts both `range` and `campfire`.
- Use `null` only for recipes designed to work anywhere.
- Add a fixed station through `StationDef`, give its semantic entity the same `kind`, and list the recipes it exposes.

Adding a new station kind changes a shared contract. Update its renderer, interaction, validation, UI label, tests, and every caller together. Do not encode station exceptions by recipe ID.

## Regenerate assets, icons, and guides

Run these after the content and asset rows compile:

```text
npm run build-assets -- --check
npm run build-assets
npm run build-assets -- --verify
npm run icons
npm run icons:verify
npm run guide:build
```

`npm run guide:build` compiles content and bundles the read-only player guide from the same collections. Review the new rows in the guide. A missing row usually means the catalog points at the wrong resource or item, or the tier has no recipe for an expected output.

## Required checks

### Unit and reference checks

- Run `npm run typecheck` and the full Vitest suite.
- Extend `tests/gathering-production-matrix.test.ts` with the new tier expectation. Check every item, resource, recipe, station kind, icon appearance, manifest asset, and tier reference.
- Freeze the gather success, XP, yield, respawn, healing, burn, duration, and production XP formulas. New tier data should exercise those formulas without changing them.
- Test active, depleted, and respawn transitions for ore, trees, and fish.
- Test both cooking stations, raw and burnt inedibility, healing clamps, and deterministic burn results.
- Test the new log as campfire fuel, including placement failure, interruption, replacement, build XP, expiry during a batch, save and load, and no offline decay.
- Test equipment requirements, stats, icons, focus compatibility, and held appearances for every new weapon family.

### Chromium scenarios

Boot the real Vite game in Chromium. Source review and unit tests do not prove the loop works.

- Mine the tier's ore, inspect depletion and respawn, smelt its bar, make handled weapons and tools, and equip them.
- Catch its fish from a visible school, cook once at a range and once at a campfire, force a burnt result and a cooked result, then eat the cooked food.
- Fell its tree to the authored stump, make shafts and handles, then make its wand, staff, rod, shield, focus, and one handled metal item.
- Build the fire on valid ground. Check water, slope, solid, building, and resource clearance failures. Check replacement, countdown, expiry, and reload.
- Compare semantic state before and after every action. Require zero debug errors and valid water and grounding probes.

### Visual and performance checks

- Capture active and depleted ore, tree, and fish views at normal play distance.
- Capture held wand and rod views.
- Capture the campfire in daylight and an authored low-light interior. Add a surface night capture
  when the deferred day/night system exists.
- Inspect the images. A passing build does not prove the state is readable.
- Keep resource visuals instanced or batched. Check the busiest region against the 400 draw-call ceiling. One player campfire may add no more than two base draws and must reuse the ambience draw.
